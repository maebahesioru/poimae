# PoiMae（ポイ前）— 捨てる前に、ひと呼吸。

ごみの分別を「撮るだけ」で下書きし、**決めるのは自治体の公式辞典とあなた自身**。
写真は端末の外に出ません。実行時に外部APIも呼びません。

Devpost **Arbiter Hacks V1** / トラック **Rethinking Waste** への提出物です。

## 1. 課題：分別ルールは、住んでいる街で変わる

同じ品目でも、自治体が変われば行き先が変わります。このリポジトリに同梱した
2市の公式辞典を突き合わせた実測では:

| 項目 | 実測値 |
| --- | --- |
| 両市に同名で存在する品目 | 148 |
| 区分を比較できた品目 | 114 |
| **うち区分が違う品目** | **30（26.3%）** |

実際に違った例（どちらも各市の公式ページの記載）:

| 品目 | 広島市 | 札幌市 |
| --- | --- | --- |
| カイロ 使い捨て | 不燃ごみ | 燃やせるごみ |
| クレヨン | 不燃ごみ | 燃やせるごみ |
| サンダル | その他プラ | 燃やせるごみ |

4分の1が変わるのに、手元にあるのは冷蔵庫に貼った紙の分別表か、探しにくいPDFだけ。
「これはどっちだっけ」を毎週どこかで誰かが悩んでいます。**間違えると、資源が燃やされ、
危険物が不燃ごみに混ざります。**

### 誰のためか

- 引っ越したばかりで、前の街のルールが体に染みついている人
- 子どもや高齢者など、辞典の漢字や検索語にたどり着きにくい人
- 燃えるごみの日に、資源ごみを出しかけて手を止めた人

## 2. 何をするか：断定しない、を機能にした

```
写真 → OpenCVで特徴量化 → 材質の候補（根拠つき） → 自治体の公式辞典 → 候補を提示 → あなたが選ぶ
```

1. **写真**を選ぶ／撮る（端末内で処理。送信しません）
2. OpenCV が色・形・質感を数値化し、**ルールベース分類器**が「ペットボトル／紙」のように
   材質の候補を**確率と根拠つき**で出します
3. その材質語で、選択中の自治体の公式辞典を引きます
4. **候補を出して、選んでもらいます。** 写真だけで「燃えるごみです」と断定しません

名前で引くこともできます（ひらがな・カタカナ・全角半角・送り仮名の差を吸収）。
辞典に無い語は、**類語で一度だけ引き直し、その旨を画面に明記します**
（例: 広島市の辞典に「乾電池」は無く「電池 その他」に載っている）。

加えて、次の3つを出します。

- **他の自治体ではどうか**（同じ品目が別の区分になる場合の警告）
- **条件つきの注記**（「30cm以上は大型ごみ」など公式の条件を検出して表示）
- **今週のごみの日**（収集曜日はブラウザの localStorage にだけ保存）

## 3. 使い方

```bash
make setup     # .venv を作って依存を入れる
make run       # http://127.0.0.1:8765
make test      # pytest
```

`make run` のあと `http://127.0.0.1:8765/?demo=ceramic` のように開くと、
同梱のサンプル写真で一連の流れを試せます（`?demo=pet_bottle` /
`?demo=metal_can` / `?demo=cardboard`、名前で引くなら `?q=乾電池`）。
サンプルは**合成画像**（プログラムで描いた見本）で、その旨は画面にも出ます。

その他のコマンド:

```bash
make corpus    # 評価用の合成画像を作り直す
make eval      # 評価用60枚で測り直し、eval/report-test.json と eval/CONFUSION.md を更新
make shots     # スクリーンショットを撮り直す（要 make run）
make video     # スライドとスクショから video/demo.mp4 を作り直す
```

## 4. 構成

```
src/poimae/
  features.py        OpenCV: 前処理・物体の切り出し・色/形/テクスチャの特徴量
  classifier.py      特徴量 → 材質の候補（ルール表。根拠と減点つき）
  municipalities.py  自治体ルールJSONの読み込み・検索（完全一致/前方一致/部分一致/あいまい）
  advisor.py         写真や名前 → 辞典 → 候補と警告（このアプリの中心）
  crosscity.py       自治体間の差分（同じ品目で区分が違うものを検出）
  calendar.py        「今週のごみの日」の計算
  app.py             FastAPI（7エンドポイント）
static/              素のHTML/CSS/JS。CDNもwebfontも読みません
data/municipalities/ 自治体ルールJSON（差し替え可能）
tools/               合成画像生成・評価・スクリーンショット
tests/               pytest
```

詳しくは [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)（構成図は `docs/architecture.svg`）。

## 5. データ：何が公式で、何がサンプルか

| ファイル | 中身 | 位置づけ |
| --- | --- | --- |
| `hiroshima.json` | 618品目 / 10区分 | **公式**。[広島市「家庭ごみ分別50音事典」](https://www.city.hiroshima.lg.jp/living/gomi-kankyo/1021277/1003072/1026094/1008419.html)から取得（2026-10-20） |
| `sapporo.json` | 1019品目 / 14区分 | **公式**。[札幌市「家庭ごみ50音分別辞典」](https://www.city.sapporo.jp/seiso/bunbetsu/)から取得（2026-10-20） |
| `sample-dummy.json` | 34品目 / 6区分 | **サンプル（ダミー）**。実在しません。画面にも「サンプル（ダミー）」と表示します |

- 各JSONは `verified`（公式ページで確認したか）と `data_kind`（`official` / `dummy`）を持ち、
  画面のバッジと `README` のこの表が同じ値を見ています。
- 取得した生HTMLは [`evidence/sources/`](evidence/sources/) に残し、JSONには
  出典URL・取得日・生ファイル名・SHA-256 を記録しています。
- **捏造した制度はありません。** 実在の2市は公式ページの記載そのままで、
  足りない部分（サンプル市）は「架空」と明示しています。

## 6. 評価（実測）

評価用に**ホールドアウトした合成画像60枚**での実測です。詳細と再現手順は
[`docs/EVALUATION.md`](docs/EVALUATION.md)。

| 指標 | 実測値 |
| --- | --- |
| 材質分類 top-1（60枚） | **65.0%** |
| 材質分類 top-3（60枚） | 88.3% |
| 最頻クラスを答える基準線 | 10.0% |
| 写真→材質語→辞典の配管（サンプル市・60枚） | 71.7%（基準線 30.0%） |
| 同（広島市・確信をもって答えられた12枚） | 58.3%（基準線 50.0%） |
| 同（札幌市・同24枚） | 50.0%（基準線 25.0%） |

**この数字は実世界の精度ではありません。** 合成画像で測った「配管が動く証拠」です。
苦手なクラス（ガラス瓶 0%、陶磁器・生ごみ・ペットボトル 50%）も含めて全部載せています。

## 7. 限界（できないこと）

- **実写真では測っていません。** 評価は合成画像のみ。手元の実写真での精度は未測定です。
- **自治体は3つだけ**（うち1つはダミー）。日本の1718市町村のうち2市です。
- **分類できる材質は10種類**。材質が分かっても品目は1つに定まりません。
  だから候補を出して人に決めてもらう設計にしています。
- **収集日は自動取得しません。** 地域ごとに違ううえ、外部に問い合わせない設計だからです。
  曜日は利用者が入れて、ブラウザにだけ保存します。
- 辞典に無い語は、類語表（7組）で引き直すか「見つかりません」と答えます。
- 分類器はルールベースです。学習済みモデルではありません（GPUを使わず、軽く動かすため）。

## 8. 責任ある利用

- **これは「下書き」です。** 最終的な判断は、お住まいの自治体の公式情報に従ってください。
  アプリ内の出典リンクと「公式の注記」表示が、その入口です。
- 危険物（電池・スプレー缶・蛍光管・注射器など）は、**必ず自治体の指示に従って**ください。
  このアプリは「有害ごみ」という区分名を出すだけで、危険性を判定していません。
- 大型ごみ・家電リサイクル法対象品は、予約や手数料が必要です。警告は出しますが、
  手続きは代行しません。
- 自治体のルールは改定されます。同梱データの取得日は 2026-10-20 です。
- **サンプル市のデータは架空**です。実在の制度と混同しないでください。

### プライバシー

- 写真は**アップロードされた端末の外に出ません**。同じ localhost のサーバが受け取り、
  メモリ上で解析して破棄します（ディスクに書きません、ログにも残しません）。
- 外部API・CDN・解析タグ・webfont を一切読みません（`tests/test_app.py` が検査しています）。
- 保存するのは「選んだ自治体」「収集曜日」だけで、どちらもブラウザの localStorage です。
- サーバは `127.0.0.1` にだけ bind します。

## 9. AI利用の開示

- このリポジトリのコード・文書・スライドは、**AIエージェント（DeepSeek Harness 上の
  コーディングエージェント）との対話で作成**しました。人間が方向を決め、要件と制約を定め、
  出力を検証しています。
- 分類器は**学習モデルではありません**。学習済みの外部モデルは使っていません。
  ルール表の閾値は、開発用60枚の合成画像から決めています（`classifier.py` の docstring に明記）。
- 評価用画像は `tools/synth.py` が生成したもので、外部データセットは使っていません。
- 自治体データは、公式ページから取得したHTMLを `tools/build_municipalities.py` で
  JSONに変換したものです。**生成AIで文章を作ったデータではありません。**
